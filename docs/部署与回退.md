# 部署与回退

本仓库用于记录已在实机安装成功的版本，**没有后台自动刷写或一键停止框架的安装器**。当前正在运行的Jiefu无需为了归档再次安装。本节给出维护约束和回退对应关系，不能将它当作其他固件的通用刷机教程。

## 安装前核对

1. 核对产品/固件、ARM32库ABI，最重要的是七个目标文件的**原SHA**必须匹配manifest；若已经安装本版，则应匹配最终SHA，不需重复覆盖。
2. 将七个原件连同权限、SELinux上下文、原软链接状态备份至独立主机目录；不是只复制候选到同一分区。data不需要清理。
3. 保留TTL与可靠的本机文件回退渠道。不要运行工作区早期整机恢复脚本，它可能覆盖既有HDR/CEC修复。
4. 通过明确指定的ADB目标连接；不要使用无`-s`的多设备写命令，不要kill整个ADB server。公开仓库不保存用户局域网IP、MAC或设备序列号。

## 正确载荷与路径

Release解压后`rootfs/`下面只有七个文件，不能把它解释成完整ROM或整套system/vendor镜像。最终文件通常root:root、0644，写入后对各文件restorecon并核对原上下文；恢复system/vendor只读挂载，检查SHA再完成服务恢复。

`/system/framework/arm/boot-framework.vdex`的原有软链接保持，不把同一vdex当成额外独立文件。原`framework.jar`与其他boot依赖保持。

## 生效范围

- 仅替换HAL、封装库、AudioFlinger时，在停止相关音频服务后原子替换，结束时无论成功失败都需恢复音频服务；原机服务为`vendor.audio-hal-2-0`和`audioserver`。需要重新登记HDMI音频能力时使用本机原生热插拔登记流程，不能伪造功放能力。
- policy与框架预编译文件在启动相关服务/框架时读取；全套首次部署应安排正常Android整机重启并验证。
- 本机单独停止/启动zygote曾导致Wi-Fi初始化和旧netd网络ID残留，**不要用单独重启zygote代替正常整机重启**。
- remount只读失败不能阻断清理逻辑；部署和回退需用EXIT trap确保服务最终恢复，不能因为`set -e`留下服务停止。
- 修改框架期间不得让ART保留正在写入的映射。源码重建/验证脚本不处理这些在线生命周期，因此没有自动整包安装命令。
- 如修复期间需要避免电视/功放随重启关闭，先记录CEC原值，临时停用后还原；不把此临时设置写入音频包或修改系统默认行为。

## 定向回退

| 问题范围 | 回退内容 |
|---|---|
| 仅排查最终共享队列补丁 | 恢复原`/system/lib/libaudioflinger.so`，重载音频HAL/audioserver；保留其他六项修复 |
| HAL局部回归 | 恢复本轮更改前、已知可工作的对应HAL版本；不要选用被驱动拒绝的65536物理帧候选 |
| 整套音频回退 | 恢复七个匹配原件；oat/vdex必须成对恢复，再正常重启Android |

音频回退不应覆盖`services.jar`、HDR模块、Wi-Fi固件或遥控配置，不清data，不写bootloader。完整回退会重新失去TrueHD/DTS-HD修复能力，不能把旧行为当成新的修复。

此前“已修复HDR策略”的全分区备份早于本次音频和CEC长按修改，不是当前完整快照。本仓库提供可校验的音频文件归档，不包含用户data或整机备份。

## v1.0.1新增客户端堆属性

/vendor/build.prop仅修改ro.af.client_heap_size_kbyte=1536→8192，必须正常整机重启生效；不能把已有ro属性当作可普通setprop覆盖。回退仅改该值并重启，不必回退HAL等其他六项。其他自定义ROM优先应用单行变更，勿覆盖无关vendor属性。
