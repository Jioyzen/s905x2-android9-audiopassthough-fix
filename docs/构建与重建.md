# 构建与精确重建

所有脚本仅在主机读写仓库目录，不会连接ADB、停止服务或刷写分区。Python3.12+；源码构建使用Linux x86_64、NDK r28c（28.2.13676358）、API28 ARMv7。

## 一、直接获取已经验证的产物

`artifacts/rootfs/`及Release压缩包提供同一组7文件。`artifacts/SHA256SUMS`和`manifests/active-files.json`给出最终SHA；仓库版本不是V2超大物理缓冲候选或已撤回JNI版本。

```bash
python3 scripts/verify_artifacts.py
(cd artifacts && sha256sum -c SHA256SUMS)
```

## 二、从匹配原件精确重建

把**原始未修补版本**的七个文件按设备路径放在`baseline/rootfs/`，该目录不进入git。原件可以来自修改前单文件备份；已经修改过的在用文件不能冒充原件。脚本逐个检查原SHA，不匹配立即退出。

```text
baseline/rootfs/vendor/lib/hw/audio.primary.amlogic.so
baseline/rootfs/vendor/lib/libdroidaudiospdif.so
baseline/rootfs/vendor/etc/audio_policy_configuration.xml
baseline/rootfs/system/framework/arm/boot-framework.oat
baseline/rootfs/system/framework/boot-framework.vdex
baseline/rootfs/system/lib/libaudioflinger.so
baseline/rootfs/vendor/build.prop
```

```bash
python3 scripts/reconstruct.py
```

输出`build/reconstructed/rootfs/`。HAL、框架、policy、AudioFlinger依据`patches/*.json`重建；新封装库本身是源码重新链接生成的独立文件，精确重建模式复制已归档版本。所有输出再次验证最终SHA，不存在旧全量boot缓存替换或网络写入。

补丁格式：每段保存文件偏移、原字节hex、zlib+base64后的新字节，含新增段；清单还含原件/最终SHA及长度。记录的是最终二进制实际差异，并不把重新编译与应用二进制差异混为一谈。

## 三、从C / 汇编源码构建

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
export ANDROID_NDK_ROOT=/path/to/android-ndk-r28c
# 或 export NDK_BIN=/path/to/ndk/toolchains/llvm/prebuilt/linux-x86_64/bin
python3 scripts/build_hal.py
python3 scripts/patch_framework_tables.py
python3 scripts/build_flinger.py
python3 scripts/build_packer.py
python3 scripts/patch_client_heap.py
```

输出：

| 入口 | 主要输出 |
|---|---|
| build_hal.py | build/audio.primary.amlogic.so、hooks.elf/bin、hal-patch.json |
| patch_framework_tables.py | build/boot-framework.oat、boot-framework.vdex、framework-table-patch.json |
| build_flinger.py | build/flinger/libaudioflinger.so、flinger-buffer.elf/bin、flinger-patch.json |
| patch_client_heap.py | build/vendor.build.prop，客户端堆单行属性修正 |
| build_packer.py | build/libdroidaudiospdif.so、ffmpeg_hdpack.o及解包头文件 |

policy为已归档文本，可查看diff或由精确重建工具生成。本次已在新仓库目录实际重建HAL、AudioFlinger、两份框架表补丁和封装库，五个输出SHA均与实机有效产物完全一致；policy由精确差异重建也一致。封装构建通过`-ffile-prefix-map`规范化编译器`__FILE__`路径，避免换目录改变断言字符串及二进制。记录见`verification/repository-rebuild.json`。更换工具链或依赖后仍应重新核验，不能直接当成已验收产物。

## 四、机器码测试

完成源码构建后：

```bash
python3 tests/test_hal_hooks.py
python3 tests/test_flinger.py
```

检测器完整测试还需要本地`fixtures/dts.dts`、`dts-full.dts`、`dtshd.dts`测试输入，片段不随公开仓库分发：

```bash
python3 tests/test_detector.py
```

该测试使用实际Thumb机器码，包含EXSS跨块、core内假同步、EDID拒绝、HW_AV_SYNC/已封装/96k排除、6.1不误升级及写路径寄存器/栈验证。`verification/`保留本次实机修复时的原验证结果，新的输出写在`build/`，不会覆盖历史证据。

`probes/TrackBufferProbe.java`只构造/查询/释放音轨，不写入、不播放；归档输出在`verification/track-buffer-installed.txt`。`probes/packer_probe.cpp`把测试输入封装到文件，不操作硬件播放。要在新环境运行这些探针，需要自行使用NDK/javac/d8构建，并明确选择目标设备，仓库不隐式连接某个IP。

## 五、依赖来源与可替换链接

`manifests/dependencies.json`固定参考项目提交、FFmpeg提交、冻结静态库/生成头文件和源包哈希。当前封装库由本仓库C++/C/汇编源码与冻结ARMv7静态库重链接；不依赖仓库外的临时目录。

`third_party/FFmpeg-n8.1.3-source.tar.xz`是对应完整干净git源码；`third_party/ffmpeg-armv7/config.h`保留实际configure配置。若重编FFmpeg，可使用该配置（将其中历史工具链路径替换为本机NDK）重建`libavformat.a/libavcodec.a/libavutil.a`并放回冻结依赖目录，再运行build_packer.py重新链接。本项目未执行一次新的完整FFmpeg源码构建并声称字节级一致，冻结依赖重链接和原始库来源已明确区分。
